# Hermes Personal README Entry-Point Framing Experiment

Date captured: 2026-07-04

## Context

In a Product 001 passive-revenue scout run, all repo/harness audits were green and several deeper buyer-facing files had already been cleaned up. A read-only adversarial reviewer still found that the product README — the workspace entry point — carried the old rejected framing:

- title/lead still said “Local Service Missed-Call Recovery AI Pack”;
- promise still described a “PDF + source map + prompt/blueprint pack”;
- buyer question was meta: “What is one practical AI automation offer I can sell...”;
- audience still split primary agency buyers and direct local-service owners.

Karan’s blocker was value clarity: the buyer, use, and product value were not obvious, and the framing was too self-referential.

## NotebookLM synthesis pattern

When the three-notebook scout returns mixed recommendations:

- AI OS / Strategic Engineering may recommend evaluator harnesses or strategic gates.
- Ai money may recommend buyer-language or demand validation.
- If the repo entry point still tells the old story, update the entry point first. It is intent debt for both future agents and buyers.

Do not rebuild exports or approval packets before the entry point matches the clarified product promise.

## One-surface experiment pattern

Surface: `post/listing angle` or equivalent entry-point framing.

Baseline scan example:

```text
AI Pack
PDF + source map + prompt/blueprint pack
validate a practical missed-call recovery / follow-up automation offer
Secondary:
What is one practical AI automation offer
```

Change only the entry-point file. Keep title propagation, pricing, sample posts, buyer-demand research, and dist rebuilds as separate experiments unless explicitly authorized.

## Good replacement shape

Lead with:

```text
I am: <single buyer>
I have: <specific situation/problem>
This helps me: <specific use/action>
So I can: <specific outcome or decision, without guarantees>
```

For Product 001, the clarified entry point became:

- buyer: AI automation freelancer or tiny agency preparing for a local-service discovery call;
- problem: vague missed-call follow-up idea without a way to test whether the business has the problem;
- use: run a short missed-call discovery audit using the owner’s workflow, call sources, and follow-up rules;
- decision: propose a simple human-reviewed follow-up queue, keep researching, or walk away.
